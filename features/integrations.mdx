以下是一个使用 Apps Script 通过 Gmail API 发送邮件的示例：

```javascript
/**
 * 使用 Google Apps Script 通过 Gmail 发送格式化邮件
 * 在 Apps Script 编辑器中直接运行此函数
 */
function sendNotificationEmail() {
  // 收件人邮箱地址
  const recipient = "colleague@example.com";

  // 邮件主题
  const subject = "【自动通知】Google 表格数据更新提醒";

  // 邮件正文（支持 HTML 格式）
  const body = `
    <h2>数据更新通知</h2>
    <p>您好，</p>
    <p>以下 Google 表格已于 ${new Date().toLocaleString("zh-CN")} 完成数据更新，请查阅：</p>
    <p><a href="https://docs.google.com/spreadsheets/d/YOUR_SHEET_ID">点击查看表格</a></p>
    <p>此邮件由自动化脚本发送，请勿直接回复。</p>
  `;

  // 调用 GmailApp 服务发送邮件
  GmailApp.sendEmail(recipient, subject, "", {
    htmlBody: body,          // 使用 HTML 格式正文
    name: "自动化通知系统",   // 发件人显示名称
  });

  // 在执行日志中记录发送结果
  Logger.log("邮件已成功发送至：" + recipient);
}
```

<Note>
  Apps Script 脚本运行在 Google 的云端服务器上，您可以为脚本设置**时间触发器**（每天/每小时自动运行）或**事件触发器**（表单提交、文件修改时触发），无需手动执行。
</Note>

## Webhook 与推送通知

对于需要实时事件驱动集成的场景，**Google Cloud Pub/Sub** 是推荐的消息传递方案。Pub/Sub 提供了可靠、可扩展的发布/订阅消息模型，支持将 Google Cloud 服务产生的事件（如 Cloud Storage 文件上传、BigQuery 数据更新、Cloud Logging 告警等）实时推送至您的下游系统。

以下示例演示如何使用 `gcloud` CLI 创建 Pub/Sub 主题与推送订阅：

```bash
# 第一步：创建 Pub/Sub 主题（用于接收 Google Cloud 事件）
gcloud pubsub topics create google-events-topic \
  --project=YOUR_PROJECT_ID

# 第二步：创建推送订阅，将消息实时推送至您的 Webhook 端点
gcloud pubsub subscriptions create google-events-subscription \
  --topic=google-events-topic \
  --push-endpoint=https://your-server.example.com/webhooks/google \
  --ack-deadline=60 \
  --project=YOUR_PROJECT_ID

# 第三步：为推送端点配置身份验证（推荐使用服务账号）
gcloud pubsub subscriptions modify-push-config google-events-subscription \
  --push-endpoint=https://your-server.example.com/webhooks/google \
  --push-auth-service-account=pubsub-invoker@YOUR_PROJECT_ID.iam.gserviceaccount.com \
  --project=YOUR_PROJECT_ID

# 验证订阅配置是否正确
gcloud pubsub subscriptions describe google-events-subscription \
  --project=YOUR_PROJECT_ID
```

当 Pub/Sub 向您的 Webhook 端点推送消息时，消息体将以 Base64 编码的 JSON 格式传递，您的服务器需要解码后处理业务逻辑，并在 60 秒内返回 HTTP `200` 状态码以确认消息已成功接收。

## REST API 集成概览

Google 的 API 生态提供了数百个 REST 接口，以下是企业集成中最常用的三种模式：

| 集成模式 | 说明 |
|---------|------|
| **批量请求（Batch Requests）** | 将多个 API 调用合并为单个 HTTP 请求发送至 `https://www.googleapis.com/batch`，可显著减少网络往返次数，提升数据批量处理效率，适用于需要同时操作大量资源的场景 |
| **服务账号认证** | 使用 Google Cloud IAM 服务账号进行 API 认证，适合服务器间（Server-to-Server）的自动化集成场景，无需用户交互即可完成身份验证，是后端系统调用 Google API 的推荐方式 |
| **OAuth 2.0 用户授权** | 当您的应用需要代表用户访问其 Google 数据（如 Gmail、Drive、Calendar）时，使用 OAuth 2.0 授权流程获取访问令牌。用户在授权页面明确同意后，您的应用才能在授权范围内操作其数据 |
